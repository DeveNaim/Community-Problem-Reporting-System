Community Problem Reporting System (CPRS)

System Design, Stakeholder Architecture, API Reference & Developer Guide
Version: 2.0.0 | Updated: October 2026 | Technology: MERN Stack (MongoDB, Express.js, React 18, Node.js, Chart.js)

Executive Summary: The Community Problem Reporting System (CPRS) is a transparent, trackable civic management platform that allows citizens to report neighborhood problems (road damage, waste accumulation, water leakage, streetlights, drainage, security) directly to municipal authorities, with dedicated Admin and Authority sidebar portals, Chart.js analytics, CSV export, and automatic email-pattern department filtering.

1. Role Portals & Responsibilities

User Role Portal & Layout Key Responsibilities
Citizen Public & Citizen Portal (Layout.jsx) Submits complaints with up to 3 photos, receives a tracking ID (CPRS-YYYYMMDD-XXXXXX), edits/deletes own complaints (with confirmation modal), and tracks live timelines & notifications.
Admin Admin Portal (AdminLayout.jsx — /admin/*) Operates inside a collapsible sidebar dashboard with Chart.js Analytics & CSV Export, Admin/Citizen/Authority/Category management, and full complaint triage (Verify, Reject, Assign, Edit, Delete).
Authority Authority Portal (AuthorityLayout.jsx — /assigned/*) Follows the same collapsible sidebar layout as Admin. Automatically detects the department category from the email token (after . and before @), locks the category filter, updates statuses, and views department Chart.js analytics.

3. Complete REST API Endpoints

Route Group Endpoints Description
Auth (/api/auth) POST /register, POST /login, POST /forgot-password, POST /reset-password, GET|POST /seed Citizen registration, JWT authentication, password recovery, and idempotent default account seeding.
Users (/api/users) GET|PUT /me, GET /, GET /:id, POST /, PUT /:id, PUT /:id/status, DELETE /:id Profile management and Admin CRUD + account status activation/blocking.
Categories (/api/categories) GET /, POST /, PUT /:id, DELETE /:id Dynamic problem category listing and Admin category management.
Complaints (/api/complaints) POST /, GET /mine, GET /assigned, GET /, GET|PUT|DELETE /:id, PUT /:id/verify, PUT /:id/assign, PUT /:id/status Full complaint submission, role-scoped listing, verification, authority assignment, status updates, editing, and deletion.
Notifications (/api/notifications) GET /, PUT /:id/read, PUT /read-all In-app citizen alerts for complaint lifecycle transitions.
Analytics (/api/analytics) GET /summary, GET /export KPI totals, status/category breakdowns, 14-day daily intake trend, and CSV report export.

4. Centralized Monorepo Commands

npm run seed           # Seed MongoDB with 10 test accounts and 7 sample complaints
npm run dev            # Start Express API (:5000) and Vite React Client (:5173)
npm run build          # Build production client bundle (client/dist/)
